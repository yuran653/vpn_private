Автоматизированный конвейер распознавания многотомных судебных дел и юридической документации на русском языке, разработанный по методологии Spec-Driven Development (SDD). 🏛 Архитектурная схема и послойное разделение системы
High-Level Design

Система следует строгому однонаправленному многослойному паттерну в соответствии с docs/architecture.md. Внешние ресурсы (файловая система, LLM-модели, сетевой стек) изолированы и инжектируются извне. Ядро обработки полностью отвязано от интерфейсов входа.

1. Уровень оркестрации

Скрипт src/run_volumes.sh управляет пакетным последовательным выполнением томов с остановкой при первой ошибке (fail-fast).

2. Ядро конвейера

Модуль src/pdf_image_ocr.py объединяет рендеринг через PyMuPDF, распознавание страниц, валидацию и парсинг артефактов.

3. Шлюз OpenRouter

Адаптер OpenRouterClient обеспечивает отказоустойчивый роутинг запросов с автоматическим переключением на резервные платные шлюзы.

⚡ Полный жизненный цикл обработки документа
Page State Machine

Пошаговый цикл обработки каждой отдельной страницы дела через конвейер распознавания: рендеринг, детекция ошибок, повторные попытки, ветвление артефактов и атомарный откат.

1. Рендеринг и изоляция

Исходный PDF конвертируется по 20 листов в PNG и JPEG с разрешением 150 DPI. Чанкование предотвращает переполнение памяти процесса.

2. Защита от галлюцинаций

Паттерны фраз-отказов («I cannot read», «As an AI») или английский комментарий триггерят повторный запрос (до 3 раз) с автоматическим переключением шлюза.

3. Ветвление экстракторов

Текст направляется в .txt, таблицы преобразуются в полноценный .xlsx с сохранением чисел, а фотографии вырезаются в отдельные JPG.

🧠 Стратегия OCR-движков и каскадирование OpenRouter
Архитектура моделей

Система предоставляет гибридную поддержку мультимодельных бэкендов. По умолчанию запросы идут в OpenRouter с нулевой стоимостью на бесплатных тарифах и автоматическим каскадным переключением на гарантированные платные шлюзы при лимитах частоты или 429 ответах.

⚡ Механизм каскадного переключения (Fallback Cascade)
  • • Шаг 1: Отправка страницы на бесплатный шлюз (:free).
  • • Шаг 2: При получении HTTP 429, 502, 503 или таймаута — немедленный повтор на платном шлюзе без :free.
  • • Шаг 3: При сохранении ошибки — экспоненциальный бэкофф с задержкой до 3 попыток.
  • • Шаг 4: При отказе модели или некириллическом выводе — перегенерация промпта.
🛡 Валидация вывода модели
  • • Детекция английских реплик: Проверка отсутствия галлюцинаций («Here is the text...»).
  • • Валидация JSON: Строгий парсинг блоков <tables> и <photos>.
  • • Контроль символов: Защита от перевода кириллицы на латиницу.
  • • Координатная сетка: Нормализация рамок фото (ymin, xmin, ymax, xmax в масштабе 0–1000).

🌐 Целевая веб-архитектура
Планируется
  • 1.
    Аутентификация и белый список: Вход через Google OAuth 2.0 в связке с обязательным TOTP (Google Authenticator) и валидацией по разрешенному списку корпоративных email.
  • 2.
    Облачное хранилище через Google Drive: Подключение общих дисков для исходных PDF и зеркалирования архивов распознавания, снимающее ограничения локального хранилища.
  • 3.
    Интерактивное разрешение нетекстовых схем: Веб-интерфейс оператора для обработки остановок на чертежах: предпросмотр, пропуск, аннотирование или ручная нарезка.
  • 4.
    Асинхронная очередь задач: Фоновые воркеры (FastAPI / Celery / Redis) для последовательного выполнения ресурсоемких пайплайнов без блокировки HTTP-сервера.
